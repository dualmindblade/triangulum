## Proposed harness work

**1. `pick X Y` — dump the ground lat/lon under a screen pixel.** V-2 had to
reconstruct the projection in Python from `camera.rs` and says it became the
single most useful function in its script. This is the tool that lets any agent
or human point at a defect in a screenshot and get coordinates back — it
composes with `repro_shot.py` to turn "this looks wrong" into a repro
automatically. **Strongly recommend.**

**2. `probe` should print `koppen`.** V-2 had to parse `assets/face_*.bin`
directly to scout a biome ecotone, duplicating `planet.rs`'s loader. Small fix,
removes a whole class of duplicated effort.

These two plus V-1's request (a first-pose trace line and optional wall-clock
timestamps in `run.log`) are all small harness-observability items. They would
make a good single bundled mission rather than three separate ones.

## A bug in an existing gate

**`world_reel.lint_grid`'s water mask is `b > g + 8`, which misses turquoise
shoal water (~90,180,180).** So the lint is silently not looking at shallow
water — which is precisely where the shading seams it was written to catch
would appear. Worth fixing when someone is next in that file; it is a
correctness hole in a gate, not a cosmetic issue.

## My spec errors, recorded so I stop repeating them

- **I proposed the algorithm instead of the observation.** I specified
  "histogram axis-aligned run lengths" as the staircase metric. That is the
  wrong invariant — the lattice is world-aligned and its screen projection
  depends on yaw, and run length is confounded by honest voxel stepping. V-2
  spent ~90 minutes implementing it faithfully before the numbers showed it
  anti-correlated. **Future specs state the observation to be made and leave
  the method to the agent**, which knows the material better by the time it
  writes code.
- **"Reuse world_reel's coordinates, they're known-good" was my line, and it
  was wrong** — it is what cost the most time, because two of the six sites I
  suggested contain nothing. I asserted "known-good" from the poses' names. That
  assumption is now B-20.

Both errors share a root: I stated things confidently about a codebase I had
read but not measured. The fix is not "be vaguer" — it is to mark which claims
in a spec are verified and which are assumptions the agent should check.
